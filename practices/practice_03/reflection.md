## Реализация эндпоинтов

Реализовал `GET /weather/{city}` и `POST /subscribe` с помощью Roo Code. Ключевой вывод: передача конкретных `@file` вместо `@codebase` даёт агенту точный контекст без шума. Для `GET /weather` передал `@docs/report_p2.md` — агент сразу реализовал cache-aside и правильный маппинг ошибок OWM. Без этого артефакта коды ошибок были бы произвольными.

Правила в `.roo/rules.md` устранили неоднозначность: без таблицы маппинга ошибок агент в разных чатах давал разные HTTP-коды для одинаковых ситуаций.

## MCP, Skills

### Что сработало

**TickTick MCP** оказался самым наглядным: задача создалась реально в приложении, агент вызвал `add_task` без подсказок. Это единственный MCP, где было видно мгновенный результат вне IDE.

**Skills** срабатывали автоматически без явного упоминания названия — достаточно было запроса, соответствующего описанию скилла.


### Что пошло не так

**GitHub MCP** выдавал 404 — токен был создан без `read:org`, поэтому не видел репозиторий организации `ai-course-avito`. После создания нового токена с правильными скопами заработал.

**MCP Memory** не вызывался автоматически: агент предпочитал читать файлы (`AGENTS.md`, `docs/`, `rules.md`) вместо `search_nodes`. Надёжно сработало только когда в памяти хранился факт, которого не было ни в одном файле и был явный запрос на поиск в memory


### Выводы

- MCP полезен, когда результат выходит за пределы IDE
- Skills работают предсказуемо 
- Memory не заменяет файлы — нужно хранить только то, чего нет в коде: историю решений, баги, договорённости
- Самый рабочий MCP в проекте — **TickTick**
